## Среда и воспроизведение

Windows, .NET SDK 10.0.401, целевая платформа .NET 8, MySQL Server 8.4.11. На компьютере нет общего ASP.NET Core 8 Runtime, поэтому API-suite выполнялся на изолированной локальной копии .NET/ASP.NET Core 8.0.25 из уже существующего кэша. Она находится только в `.artifacts/test-runtime` и не установлена в систему. Это описание тестовой среды, не рекомендация фиксировать устаревшую runtime-версию в Production; для развёртывания нужны актуальные исправления.

```powershell
dotnet build InventorySystem.slnx
dotnet run --project EasyDo/Tests/EasyDo.Core.Specs
dotnet run --project EasyDo/Tests/StockFlow.Specs
./EasyDo/Tests/Run-IsolatedMySql.ps1 -IncludeApi
```

Для нестандартной локальной установки host путь можно передать через `-ApiDotnetPath`. Suite требует доступного ASP.NET Core 8 Runtime либо эквивалентной локальной копии. Инструкция стандартной установки — [SETUP.md](SETUP.md).

## Что проверено

**Данные и транзакции.** Создание схемы дважды, каталог, категории, поиск, дробные цены, история цен, приход, продажи, стоимость/прибыль и история чеков. Принудительная ошибка при записи позиции откатывает заголовок чека и остатки. Параллельные кассы не продают последнюю единицу дважды. Обратный порядок товаров в корзинах не меняет порядок блокировок.

**API и целостность.** Отказ анонимному пользователю, серверные роли, диапазоны входных данных, поиск с SQL-подобным текстом, конфликт артикула, конфликт устаревшей версии, запрет передачи цены в строке продажи. Последовательные и конкурентные повторы одного Idempotency-Key возвращают один чек. Другой состав корзины с тем же ключом даёт конфликт. Неуспешная транзакция не оставляет ключ занятым. Удаление товара сохраняет снимки его названия и цен в чеке.

**Вход и защита.** Разные соли паролей, хранение только хэшей токенов, неверный пароль, истечение/неизвестный токен, logout, отзыв всех сессий после смены пароля или отключения. Пять ошибок фиксируют блокировку в БД. Проверяется лимит входа по IP. Production-конфигурация отвергает непроверяемое TLS-подключение к MySQL и HTTP-адреса, включая отдельные Kestrel endpoints.

**Реальный HTTPS.** Kestrel запускается с временным сертификатом. Тестовый клиент доверяет только его точному отпечатку; обычный InventoryApi отвергает этот самоподписанный сертификат. Рабочий клиент не имеет выключателя проверки TLS. Самостоятельный процесс `Inventory.Server` выполняет `create-user`, инициализирует схему и создаёт пользователя; пароль передаётся stdin и не появляется в stdout.

**Контракт.** 24 operationId OpenAPI совпадают с зарегистрированными маршрутами. Документ содержит 20 схем. Пользовательские ответы не содержат password/token hash, запрещено кэширование.

## Границы

Проверки не являются пентестом, нагрузочным тестом или подтверждением работы на всех версиях ОС/DPI. Полная поддержка reverse proxy, несколько серверных инстансов, CI и автоматический выпуск релизов не заявляются. Тестовые базы создавались с уникальными именами и удалялись в finally; отдельные MySQL/HTTPS-серверы остановлены. Основная база и реальные учётные записи не использовались.
