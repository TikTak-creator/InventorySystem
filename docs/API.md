# StockFlow API v1

Базовый URL разработки: `https://localhost:7071/api/v1`. Формат — JSON, имена полей `camelCase`, даты ISO 8601. Версия протокола указана в пути. OpenAPI 3.0: [Inventory.Server/openapi.json](../Inventory.Server/openapi.json); тот же документ доступен после входа по `GET /api/v1/openapi.json`.

## Вход

`POST /auth/login`:

```json
{ "username": "your-login", "password": "your-password" }
```

Успешный ответ:

```json
{
  "accessToken": "opaque-random-session-token",
  "expiresAt": "2026-10-16T12:00:00+00:00",
  "user": { "id": 1, "username": "your-login", "role": "Admin" },
  "tokenType": "Bearer"
}
```

Токен — непрозрачная случайная строка, не JWT. Передавайте его в `Authorization: Bearer <accessToken>` для остальных запросов. Не помещайте пароль или токен в URL. Срок по умолчанию — 60 минут; серверная настройка `Security:SessionMinutes` допускает 5–480. Продления/refresh-токена нет: после истечения нужен новый вход.

`GET /auth/me` возвращает текущие ID, логин и роль. `POST /auth/logout` отзывает текущий токен (204). Смена пароля или отключение пользователя отзывает все его сессии. Единственные публичные операции — HTTPS `/health` и вход.

## Роли

| Возможность | Viewer | Operator | Admin |
|---|---|---|---|
| Товары, закупочные цены, остатки, чеки, прибыль и отчёты | Да | Да | Да |
| Создание/редактирование товаров, приход, продажи | — | Да | Да |
| Удаление товара | — | — | Да |
| Создание пользователей, смена паролей, отключение | — | — | Да |

Роли проверяются сервером на каждом запросе; отключённая кнопка интерфейса не является защитой. Это система одного магазина, без разделения данных по организациям или складам.

## Операции

Пути в таблице приведены относительно `/api/v1`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/products?search=&category=&lowOnly=false&offset=0&limit=100` | Массив товаров |
| GET | `/products/{id}` | Один товар |
| GET | `/products/categories` | Массив категорий |
| GET | `/products/sku-exists?sku=...&excludeId=0` | `{ "exists": true }` |
| POST | `/products` | 201, `{ "id": ... }`, Location |
| PUT | `/products/{id}` | Обновление, 204 |
| DELETE | `/products/{id}` | Удаление, 204 |
| POST | `/products/{id}/stock` | Приход, 204 |
| GET | `/products/{id}/price-history` | История цен |
| GET | `/sales?from=2026-10-01&to=2026-10-16&offset=0&limit=100` | Чеки за включительный период |
| GET | `/sales/recent?count=12` | Последние чеки |
| GET | `/sales/{id}/items` | Состав чека со снимками названия и цен |
| POST | `/sales` | `{ "id": ..., "total": ... }` |
| GET | `/dashboard/stats` | Показатели магазина |
| GET | `/dashboard/revenue?days=7` | Массив `{ "day": ..., "total": ... }` |
| GET | `/users` | Пользователи без паролей и токенов |
| POST | `/users` | Созданный пользователь, 201 |
| PUT | `/users/{id}/password` | Смена пароля и отзыв сессий, 204 |
| PUT | `/users/{id}/active` | Изменение активности и отзыв сессий, 204 |

Для списков товаров/чеков `limit` — 1–200, `offset` — от 0. Массив короче limit означает конец списка. Данные могут измениться между страницами, поэтому это не snapshot-экспорт. Для чеков разница между from и to — не более 366 дней; `count` — 1–100; `days` — 1–366.

## Товар и защита от устаревшего сохранения

```json
{
  "sku": "SKU-100",
  "name": "Новый товар",
  "category": "Бакалея",
  "purchasePrice": 80.00,
  "price": 100.50,
  "quantity": 20,
  "minQuantity": 5
}
```

Название и артикул обязательны, максимум 200 и 50 символов; категория — до 100. Цены — до 10000000, не более двух десятичных знаков; цена продажи положительна, закупка неотрицательна. Остаток и минимум — 0–1000000. Приход: `{ "quantity": 10 }`, 1–1000000; итоговый остаток также ограничен.

Для PUT сначала получите товар, сохраните его `id` и **исходный `updatedAt`**, измените нужные поля и отправьте объект обратно. `updatedAt` используется как непрозрачная версия и монотонно меняется при редактировании, приходе и продаже. Его не нужно заменять временем клиента. Если товар изменился, сервер вернёт 409: перечитайте карточку и предложите пользователю применить изменения к новой версии. Это защищает остатки от перезаписи старой открытой карточкой.

`isLow`, `stockValue`, `status` вычисляются сервером и не являются изменяемыми полями. При создании входящий id игнорируется. Нераспознанные поля JSON отвергаются.

## Продажа и безопасный повтор

Отправьте `Idempotency-Key` — новый UUID формата D для новой операции:

```http
POST /api/v1/sales
Authorization: Bearer <token>
Content-Type: application/json
Idempotency-Key: 3d531c34-245f-4918-9ce3-d5af70057e01

{ "items": [ { "productId": 42, "quantity": 2 } ] }
```

Корзина содержит 1–100 строк. Количества — 1–1000000, ID положительны. Цены и себестоимость передавать нельзя: они читаются из БД в транзакции. Повторяющиеся товары объединяются перед проверкой остатков.

При таймауте или потере ответа повторите **тот же ключ и ту же корзину под тем же пользователем**. Сервер вернёт исходный чек без повторного списания. Другие товары/количества с тем же ключом дают 409. Для новой продажи нужен новый ключ. Ключи изолированы по пользователям. После неуспешной транзакции ключ не остаётся занятым. Ключи успешных продаж хранятся вместе с привязкой к чеку; автоматического срока удаления нет.

Не повторяйте автоматически изменение товара, приход или создание пользователя: гарантии идемпотентности относятся к POST /sales. При изменении цены с момента загрузки корзины применяется актуальная цена сервера; `total` ответа является окончательным.

## Пользователи

Создание (Admin):

```json
{ "username": "cashier-01", "password": "a-long-unique-password", "role": "Operator" }
```

Логин — 3–64 латинских буквы/цифры/`_.-`; сравнение без учёта регистра. Пароль — 12–128 символов. Смена: `{ "password": "another-long-unique-password" }`. Отключение: `{ "active": false }`. Собственный аккаунт текущий администратор отключить не может. Первого администратора создаёт серверная команда, инструкции — [SETUP.md](SETUP.md).

## Ошибки и ограничения

400 — ошибка параметров/JSON; 401 — нет/истёк/отозван токен или неверный вход; 403 — недостаточно прав; 404 — объект не найден; 409 — конфликт версии, артикула, остатков или ключа повтора; 413 — тело больше 64 KiB; 429 — лимит запросов; 500 — внутренняя ошибка без SQL/секретов в ответе. Framework-ошибка разбора тела может вернуть пустой ответ 400; клиент должен обрабатывать HTTP-статус, не полагаясь на наличие тела.

```json
{
  "type": "about:blank",
  "title": "Request failed",
  "status": 409,
  "detail": "Товар изменился. Обновите список перед сохранением.",
  "traceId": "request-trace-id"
}
```

Ответы имеют `Cache-Control: no-store`. Общий лимит — 300 запросов/IP/минуту, вход — 10/IP/минуту. После пяти неверных паролей аккаунт блокируется на 15 минут; в ответе входа причина не раскрывается. При 429 проверяйте Retry-After. Лимиты IP действуют на один процесс сервера и не заменяют внешний DDoS/WAF-контроль.

## C#-интеграция

Подключите `Inventory.Client.csproj` и `Inventory.Contracts.csproj` (второй подключается транзитивно):

```csharp
using Inventory.Client;
using Inventory.Contracts;

using var api = new InventoryApi("https://stockflow.example.com:7071");
await api.LoginAsync(username, password, cancellationToken);
var products = await api.GetAsync<List<Product>>("api/v1/products?limit=100", cancellationToken);
var requestKey = Guid.NewGuid().ToString("D");
var cart = new CreateSaleRequest([new SaleLineRequest(products[0].Id, 1)]);
var receipt = await api.CreateSaleAsync(cart, requestKey, cancellationToken);
await api.LogoutAsync(cancellationToken);
```

Сохраните requestKey на время восстановления конкретной операции; повтор используйте с тем же телом. SDK не делает автоматических повторов записей. Пароль не сохраняется, токен остаётся в памяти; 401 очищает локальную сессию. В production нельзя подменять проверку TLS пользовательским HttpClient с отключённой валидацией.

PowerShell-пример без записи пароля на диск:

```powershell
$base = "https://localhost:7071/api/v1"
$credential = Get-Credential
$body = @{ username = $credential.UserName; password = $credential.GetNetworkCredential().Password } | ConvertTo-Json
$login = Invoke-RestMethod -Method Post -Uri "$base/auth/login" -ContentType "application/json" -Body $body
$body = $null
$headers = @{ Authorization = "Bearer $($login.accessToken)" }
Invoke-RestMethod -Uri "$base/products?limit=100" -Headers $headers
Invoke-RestMethod -Method Post -Uri "$base/auth/logout" -Headers $headers
```

Не сохраняйте вывод входа, токены или тела с паролями в общие логи/историю команд. Сертификату сервера должен доверять компьютер интеграции.
